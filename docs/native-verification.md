# Local Files 2.0 — проверка 4 октября 2026

macOS-сборка установлена в `~/Applications/Local Files.app`; существующий туннель переключён на Rust MCP. Проверены протокол, ограничения чтения, работа конфигурации и готовность туннеля. Полная пользовательская приёмка пока не завершена: системный запрос доступа к Documents ожидает ответа, а взаимодействие с нативным меню ещё не проверено.

## Измерения

macOS 26.5.2, arm64, rustc 1.98.1, Node v26.9.0. Четыре новых процесса каждой реализации, в каждом пять поисков и чтений; порядок Node/Rust чередуется. Медиана, прогретый файловый кеш. 257 синтетических файлов, 30 208 047 байт. Исходные измерения: [benchmark-2026-10-04.json](benchmark-2026-10-04.json).

| Показатель | Node | Rust |
|---|---:|---:|
| Запуск и MCP initialize | 83,43 мс | 6,26 мс |
| RSS после initialize | 71,13 МиБ | 10,01 МиБ |
| Полный поиск отсутствующей русской фразы | 55,00 мс | 21,35 мс |
| Чтение 64 000 символов | 1,18 мс | 0,95 мс |
| RSS после нагрузки | 85,06 МиБ | 12,92 МиБ |

В этом сценарии сервер использует примерно в 7,1 раза меньше памяти после initialize; полный поиск быстрее в 2,6 раза. Это не обещание для любых документов и дисков. OCR, индексирование и сеть коннектора в измерение не входят. Метрика RSS не равна уникально занятой физической памяти.

Туннель и интерфейс — отдельные процессы. Снимок установленного приложения перед обращением к реальным документам: Rust MCP 7,6 МиБ RSS, интерфейс 43,9 МиБ, tunnel-client 38,2 МиБ. В снимке у GUI и MCP был 0% CPU; это не длительный замер энергопотребления. Суммировать RSS как точный физический расход всей связки нельзя.

## Выполненные проверки

- `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked` — успешно; один модульный тест свежести контрольного опроса.
- `npm run check` — 16 тестов успешно: восемь исходной Node-реализации и восемь нового Rust MCP через независимый Node MCP SDK.
- Все восемь Rust MCP-тестов успешно повторены под установленной политикой Seatbelt и отдельно на установленном подписанном бинарнике.
- Проверены девять инструментов, кириллица и emoji, диапазоны строк, бинарные ресурсы, стабильные `root:path` ID, смена конфигурации в живом MCP-сеансе, закрытие доступа при повреждённой конфигурации, недоступный корень, ограничения размера и неполная выдача поиска.
- Проверены `..`, абсолютные и Windows-пути, секретные файлы, симлинки за пределы корня и на запрещённые файлы. Именованные каналы, в том числе через симлинк, отвергаются без зависания следующего запроса. Положительный тест относительного симлинка внутри корня также проходит.
- В отдельной проверке процесса под той же Seatbelt-политикой создание файла и сетевого сокета завершилось `PermissionError`.
- `codesign --verify --strict` — успешно. Подпись локальная ad-hoc; нотариализация для распространения не выполнялась.
- После установки `/healthz`, `/readyz` и свежий успешный control-plane poll подтверждены. Команда `local-files status` возвращает `live: true`, `ready: true`, `connected: true`.
- На промежуточной Rust-сборке `list_roots` прошёл через существующий подключённый MCP-коннектор. `list_directory` реальной папки Work завершился тайм-аутом при ожидающем запросе macOS на Documents; сквозное чтение реальных документов ещё не принято.

В тесте FIFO найдено и устранено зависание `cap-std canonicalize` на macOS: разрешение пути теперь использует ограниченное число `symlink_metadata` / `read_link`, а чтение выполняется через capability handle с `O_NONBLOCK` и проверкой обычного файла. Ограничение корня по-прежнему проверяет cap-std при открытии.

## Установленный пакет и откат

SHA-256 подписанного исполняемого файла:

```text
a23b7bbce0812c791d4a6f0e30a4606713881d1e67451c7f79a1fe6300b8232b
```

Совпадает у `dist/Local Files.app/Contents/MacOS/local-files`, установленного приложения и worker в `~/.local/share/strigov-local-files-mcp/local-files`. Размер — 5 020 240 байт. Неподписанный `target/release/local-files` имеет другой хеш из-за добавления подписи.

Резервная копия перед последней установкой: `~/.local/share/strigov-local-files-mcp/backups/20261004-053500`. Более ранние снимки сохранены в том же каталоге. Автоматический откат установщика уже сработал при первоначальной неудачной попытке пересоздать существующий профиль; исправленный установщик сохраняет профиль и заменяет только команду MCP.

Для ручного отката выбранного снимка предусмотрен `python3 scripts/restore-native-backup.py BACKUP_DIRECTORY`. Он сохраняет заменяемую версию отдельно и оставляет восстановленные службы остановленными. Сам этот ручной сценарий на рабочей службе не запускался. Настройки папок и документы не откатываются этим скриптом.

- Минимальная версия Rust 1.92 указана в manifest, но эта сборка проверялась только с Rust 1.98.1.
