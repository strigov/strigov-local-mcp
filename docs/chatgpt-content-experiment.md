# Проверка передачи изображений и PDF в ChatGPT

Эксперимент Ф1 проверяет, видит ли модель содержимое MCP `image` и вложенного PDF `resource`, и какой размер ответа доходит целиком. Успешный вызов инструмента сам по себе не доказывает, что модель видит изображение. Доказательство — правильный случайный код, которого нет в имени файла или текстовом резюме ответа.

Все пробы синтетические. Не проводите эксперимент на клиентских папках. Сборку установщика, установку, подключение папки и запросы в ChatGPT выполняет пользователь. Автоматические тесты сервера не заменяют эту проверку.

## 1. Собрать и установить экспериментальную версию

В терминале из корня репозитория:

```sh
sh scripts/build-installer.sh
```

Откройте созданный DMG и запустите **Install Strigov Local MCP**. Установщик переместит прежнее приложение в папку `Strigov Local MCP backup …`. Запишите расположение этой копии.

Откройте приложение через значок в строке меню и убедитесь, что туннель работает. Проверка в терминале:

```sh
~/Applications/Strigov\ Local\ MCP.app/Contents/MacOS/local-files status
```

Ожидается `ready: true`. Запишите версию приложения и идентификатор собранного исходного кода: в этой фазе версия остаётся **2.1.2**, поэтому одного номера версии недостаточно для различения сборок.

## 2. Создать пробы и подключить папку

```sh
python3 scripts/make-mcp-experiment.py ~/MCP-experiment
```

Скрипт использует только стандартную библиотеку Python 3. Он создаст девять файлов и напечатает таблицу их точных размеров в байтах. Папка должна быть новой: повторная генерация в существующую папку запрещена. Каждый визуальный файл и каждый текстовый маркер получают отдельный случайный шестизначный код из букв и цифр.

Ответы сохраняются в `~/MCP-experiment.answers.json`, рядом с папкой. В JSON `codes` содержит соответствия «файл → код»; для `text-200k.txt` это соответствия `MARKER-n → код`. В `bytes` записаны размеры всех файлов. При необходимости можно задать другое **новое** имя вне папки проб:

```sh
python3 scripts/make-mcp-experiment.py ~/MCP-experiment-2 --answers ~/MCP-experiment-2-key.json
```

В приложении подключите **только** `~/MCP-experiment` и задайте прозвище **MCP-эксперимент**. Не подключайте родительский каталог: там находятся ответы. Не передавайте файл ответов модели и не вставляйте коды в разговор до завершения проверки. Сверяйте ответы самостоятельно, в отдельном редакторе.

## 3. Подготовить ChatGPT

В Settings → коннектор Strigov Local MCP обновите список инструментов. Создайте новый разговор, включите коннектор и запишите точное название модели и режим (например, GPT Pro / Thinking). Если нужно проверить подключение, попросите вызвать `list_roots`: в результате должно быть имя `MCP-эксперимент`.

В этой сборке `read_file` возвращает изображения PNG/JPEG/GIF/WebP без изменения байтов, с текстовым резюме первым блоком. PDF возвращаются как вложенные бинарные ресурсы с текстовым резюме. Сам сервер пока не извлекает текст PDF.

## 4. Выполнить пробы

Если изображения в ответе инструмента нет, прямо скажи об этом и перечисли, какие части ответа ты получил (text, image, resource, structuredContent). Не угадывай.

## 5. Проверить наблюдения

Разверните каждый вызов в интерфейсе ChatGPT. Запишите, завершился ли он успешно, какие блоки или поля ответа видны, была ли ошибка (например, `response too large`) и что ответила модель. Сравните код с локальным файлом ответов. Правильный код подтверждает доступ к содержимому; рассказ модели о типах блоков без правильного кода этого не подтверждает. Сохраните ошибки и случаи, когда успешный вызов дал только текстовое резюме.

Размеры в именах приблизительные (шум плохо сжимается). Для калибровки используйте точные байты из таблицы генератора или JSON. Base64 на транспорте больше исходного файла примерно на треть; в результатах нужны байты исходного файла, без этой надбавки.

## 6. Записать исход и передать оркестратору

Выберите исход по маленьким пробам:

- **A**: верно прочитан код `image-small.png`.
- **A+pdf**: выполнено A и верно прочитан код `page-scan.pdf`.
- **B**: A не выполнено, но верно прочитан код `page-scan.pdf`.
- **C**: ни A, ни B. Один успешный `page-text.pdf` также означает C.

`image_max` — наибольший размер изображения с успешным вызовом и правильно прочитанным кодом, включая A1; если таких нет, `none`. `pdf_max` — наибольший размер PDF **с изображением** с успешным вызовом и правильным кодом (B2, C4, C5); B1 в эту величину не входит. Если таких нет, `none`.

`text_max` измеряется в символах Unicode, а не байтах. Если правильно получены все пять маркеров за один вызов C6, запишите `200000`. Иначе запишите начальный offset самого позднего полностью полученного правильного маркера: MARKER-1 → `1000`, MARKER-2 → `50000`, MARKER-3 → `100000`, MARKER-4 → `150000`, MARKER-5 → `199000`. Укажите пропуски и ошибки в примечаниях. Если не получен даже MARKER-1, повторите C6: `text_max < 1000` не подходит для перехода к Ф2.

При очень малом `pdf_max` исход B может быть реализован как C, а A+pdf как A: Ф3 включает канал одностраничных PDF только при откалиброванном лимите не менее 256 KiB. Это решение принимает оркестратор по записанным значениям.

После заполнения таблицы и строки `Outcome:` отправьте их оркестратору вместе с моделью, датой и сборкой. **До результатов пользователя оркестратор останавливается; Ф2 и Ф3 не начинаются.** Ниже записаны результаты от 2026-10-18.

## 7. При необходимости вернуть прежнюю версию
