# Strigov Local MCP — нативный MCP на Rust

Приложение в строке меню macOS: выбранные папки доступны ChatGPT только для чтения через OpenAI Secure MCP Tunnel. Нативные меню и диалоги, без Docker, Node.js и WebView. Туннельный клиент входит в дистрибутив.

## Установка 2.1.1

Собранный установщик: `dist/Strigov-Local-MCP-2.1.1-macos-arm64.dmg` — macOS 13+, Apple Silicon. Откройте образ и запустите **Install Strigov Local MCP.app**. Он установит приложение в `~/Applications`, добавит запуск при входе и запустит значок в строке меню. При обновлении настройки сохраняются, старое приложение копируется рядом в папку `Strigov Local MCP backup …`.

Установщик общий: в нём **нет личных папок, ключей, профиля туннеля или привязки к аккаунту**. На компьютере пользователя не нужны Rust, Python, Node.js, Docker или Homebrew. Данные создаются при первом запуске в `~/Library/Application Support/Local Files`; ключ хранится в macOS Keychain.

При обновлении общего дистрибутива 2.1.0 прежний `Local Files.app` переносится в резервную копию и заменяется на `Strigov Local MCP.app`. Каталог настроек и системные идентификаторы сохранены для совместимости; повторно вводить ключ и выбирать папки из-за переименования не требуется.

Текущий DMG подписан ad-hoc, без Developer ID и нотариализации Apple. Это проверочная сборка; для обычного публичного скачивания нужно подписать и нотариализовать релиз сертификатом издателя. Проверены установка и обновление в изолированном каталоге на текущем Mac. Intel-сборка и Windows-установщик пока не проверены и не выпущены.

## Первый запуск и другой аккаунт ChatGPT

1. Значок серверной стойки → «Подключённые папки» → «Добавить папку…». Изначально доступных папок нет.
2. «Подключение ChatGPT» → «Создать туннель в OpenAI Platform…». Создайте свой туннель и свяжите его с нужным workspace.
3. Создайте runtime API key с правами **Tunnels Read + Use**.
4. «Настроить или сменить подключение…» → введите tunnel ID и ключ. Приложение покажет выбранный туннель и список доступных ему папок перед применением.
5. После запуска туннеля добавьте custom MCP server в своём ChatGPT, выберите **Tunnel** и этот туннель. Ваш workspace должен разрешать создание и использование таких подключений.

Для другой машины создайте отдельный туннель. Для другого аккаунта/workspace на этой машине смените подключение через то же меню. «Отключить аккаунт…» остановит туннель и удалит его ключ; список папок сохранится. Старые персональные установки автоматически не импортируются. Одновременно приложение хранит одно подключение.

[Официальная инструкция OpenAI](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels) описывает создание туннеля, права ключа и связь с workspace. Secure MCP Tunnel предназначен для частных подключений. Распространение desktop-приложения не означает публикацию плагина в каталоге ChatGPT. Авторизация другого аккаунта требует его собственных данных; в проверку дистрибутива она не входила.

## Папки и состояние

- Монохромная серверная стойка — локальный MCP готов, успешный обмен с OpenAI был не более 90 секунд назад.
- Перечёркнутая стойка — соединение не подтверждено. Причина показана в меню.
- «Закрыть значок» закрывает интерфейс; «Остановить» останавливает туннель. После сна связь восстанавливает туннельный клиент.

Папки можно добавить, заменить и отключить. Отключение прекращает доступ для новых MCP-вызовов; начатый запрос может завершиться. Файлы остаются на месте. При замене папки назначается новый ID, чтобы прежние ссылки не указывали на другие документы.

«Изменить прозвище…» задаёт понятное имя: русский текст и пробелы поддерживаются, длина 1–64 символа, повторяющиеся имена запрещены. Физическая папка не переименовывается. ChatGPT получает имя через `list_roots`; постоянный ID и ранее выданные ссылки сохраняются.

После добавления папок или изменения прозвищ обновлять коннектор не нужно: конфигурация перечитывается при каждом запросе. В старом разговоре попросите ChatGPT снова вызвать `list_roots`. После перехода со старой версии один раз обновите инструменты коннектора, если его сохранённая схема ограничивает корни именами `work` и `cowork`.

macOS может запросить доступ к выбранной папке. Готовность MCP не подтверждает разрешение на чтение каждого каталога; проверьте конкретный документ после выдачи разрешения.

## Архитектура и защита

```text
ChatGPT → Secure MCP Tunnel → встроенный tunnel-client
                                  └─ local-files worker → MCP по stdio
Strigov Local MCP.app → настройки папок и подключения + локальная диагностика
```

`tao`, `tray-icon` и `rfd` создают системное меню и диалоги. Интерфейс спит до события. Диагностика выполняется раз в 5 секунд отдельным потоком, без запуска shell на каждом опросе. MCP использует Rust SDK `rmcp` и однопоточный Tokio; одновременно выполняется одна дисковая операция. Приложение управляет только этим компьютером. Объединение Mac и Windows за одним коннектором не реализовано.

- Только чтение; нет MCP-инструментов записи, удаления, выполнения команд или сетевых запросов.
- Доступ через `cap-std` directory handles. Выход через `..`, абсолютные пути и внешние симлинки запрещён. Закрыты `.env*`, `.git`, `.ssh`, `.aws`, `node_modules` и приватные ключи. Поиск симлинки не обходит.
- Worker на macOS запускается с Seatbelt: запрещены запись, сеть и создание дочерних процессов. При отсутствии `sandbox-exec` worker не запускается. Этот устаревающий системный интерфейс проверен на текущем Mac; минимальная версия ОС задана сборкой, отдельная машина с macOS 13 не тестировалась.
- Настройки сохраняются атомарно. Некорректная конфигурация закрывает доступ. Ключ не записывается в JSON или командную строку и не передаётся MCP worker.
- Текстовый файл: до 5 МиБ; бинарный: до 15 МиБ; текст ответа: до 200 000 Unicode-символов.
- Поиск: до 128 МиБ, 20 000 элементов и 10 секунд между файловыми операциями. Ожидание внешнего диска или разрешения macOS может занять больше времени. Индекса в памяти нет.
- Недоступные корни возвращаются в `unavailableRoots`; пропуски и достижение лимита сообщаются явно.
- OCR и конвертация документов не входят в сервер. Для локальных производных используйте AnyDoc / Docling / ocrmac, сохраняя оригиналы.

## Сборка и проверка

На macOS нужны Rust, Xcode Command Line Tools и Python 3. Для тестового MCP-клиента нужен Node.js. Эти зависимости нужны разработчику, а не пользователю.

```sh
sh scripts/build-installer.sh
python3 scripts/verify-distribution.py dist/Strigov-Local-MCP-2.1.1-macos-arm64.dmg
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
npm ci --ignore-scripts
npm run check
```

`build-native.sh` выбирает архитектуру текущего Mac, получает закреплённый SHA-256 официальный runtime, удаляет локальные пути из бинарников и собирает пакеты по явному списку файлов. `build-installer.sh` создаёт DMG и SHA-256. Для подписи задайте `LOCAL_FILES_SIGNING_IDENTITY`; нотариализацию выполните отдельно. Скрипт не читает рабочие профили туннеля или Keychain.

Проверка дистрибутива монтирует DMG, устанавливает приложение в временный каталог, проверяет пустые настройки, обновление с сохранением папок и резервную копию, подписи и отсутствие личных данных. Затем запускает MCP-тесты через установленный Seatbelt worker. Результат записывается рядом в `.verification.json`. Рабочие службы и настройки пользователя не изменяются.

Сервер без GUI: `cargo build --release --locked --no-default-features --bin local-files`. Для изолированной проверки предусмотрен абсолютный `LOCAL_FILES_DATA_DIR` или `--config /absolute/path/folders.json`.

Windows-исходники содержат системное хранилище ключа и управление задачей запуска; готовность Windows требует отдельной сборки и проверки на Windows. CI-матрица добавлена, удалённый CI не запускался. Старые `install-native.py` и `install-native-windows.ps1` оставлены для истории 2.0 и отказываются устанавливать 2.1.
